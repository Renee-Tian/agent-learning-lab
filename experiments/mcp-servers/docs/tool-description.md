# MCP Tool Design — 工具设计说明

## 1. 设计目标

本实验设计两个 MCP Tools，用于探索 AI 应用如何通过工具调用获取外部信息。

两个工具分别负责关键词搜索和指定主题查询，采用不同的功能定位，避免单一工具承担过多职责。

---

## 2. Tool 1：search_knowledge

### 功能描述

根据用户提供的关键词，在模拟知识库中搜索相关内容。

### 输入参数

| 参数 | 类型 | 说明 |
|---|---|---|
| query | String | 用户输入的搜索关键词 |

### 工作逻辑

1. 接收用户输入的关键词。
2. 遍历知识库中的主题及对应内容。
3. 判断关键词是否出现在主题名称或知识内容中。
4. 返回所有匹配的结果。
5. 如果没有匹配结果，则返回提示信息。

### 示例

输入：

```text
query = "Agent"
```

输出：

```text
Agent：Agent 是能够感知环境、理解任务、
制定计划，并调用工具执行任务的智能系统。
```

### 设计特点

- 支持关键词匹配
- 可返回多个匹配结果
- 适用于探索性信息检索

---

## 3. Tool 2：get_information

### 功能描述

根据指定主题，查询知识库中对应的详细信息。

### 输入参数

| 参数 | 类型 | 说明 |
|---|---|---|
| topic | String | 需要查询的主题名称 |

### 工作逻辑

1. 接收用户指定的主题。
2. 遍历知识库中的主题名称。
3. 对主题名称进行不区分大小写的精确匹配。
4. 返回该主题对应的知识内容。
5. 如果主题不存在，则返回提示信息。

### 示例

输入：

```text
topic = "MCP"
```

输出：

```text
MCP 是模型上下文协议，
用于标准化 AI 应用与外部工具、数据源之间的连接。
```

### 设计特点

- 指定主题查询
- 不区分大小写
- 每次返回一个主题对应的内容
- 适用于明确的信息查询场景

---

## 4. 两个工具的设计区别

| 维度 | search_knowledge | get_information |
|---|---|---|
| 查询模式 | 关键词匹配 | 主题精确匹配 |
| 匹配对象 | 主题名称与内容 | 主题名称 |
| 返回数量 | 多条或无结果 | 单条或无结果 |
| 使用场景 | 搜索与发现 | 明确查询 |

---

## 5. 当前实现的局限性

当前实验采用静态字典作为模拟知识库，尚未接入数据库、搜索引擎或大语言模型。

主要局限：

- 知识内容有限
- 无法理解自然语言语义
- 不支持模糊语义检索
- 不支持动态知识更新
- 关键词匹配可能返回不够精准的结果

---

## 6. 后续优化方向

- 扩展知识库数据规模
- 接入外部数据源
- 引入向量检索，实现语义搜索
- 探索多个 MCP Server 的协同调用
- 将 MCP Tools 接入 AI Agent，实现自动工具选择与调用

---

## 7. 实验总结

通过本实验，我尝试将知识查询需求拆分为两个职责明确的 MCP Tools，并通过 MCP 协议向客户端提供标准化工具接口。

本次实践重点在于理解 MCP Tool 的定义方式、输入输出设计及功能边界，为后续 Agent 工具调用与多工具协作实验奠定基础。
